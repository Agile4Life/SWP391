# VNPay checkout — SCRUM-76 / SCRUM-102

Owner: Finance — Phong; member checkout screen — existing membership UI. Explicit user request adds VNPay beyond the original counter-only MVP.

Scope updated by user: all existing payment targets (membership purchase/renewal/upgrade, hourly PT, paid courts and pending payment records including class enrollment). Sandbox only, merchant credentials only in backend environment; counter checkout remains available. No production gateway or automatic gateway refunds.

Flow: member creates/reuses their pending subscription, requests a signed URL using subscription ID only, visits VNPay, returns to a member result page. Server-to-server IPN verifies HMAC-SHA512, merchant, immutable reference and amount before settling the existing PaymentService flow and issuing an invoice. Return query parameters never activate a subscription. Ownership applies to checkout/status APIs; only IPN is public.

Persistence: additive JPA VnpayTransaction entity/table stores immutable reference, payment, quoted amount, created/expiry timestamps, terminal outcome and VNPay transaction number. Existing payments.method uses online_wallet; provider is identified by its transaction. No DDL migrations or changes to historical schema files. Reuse member row lock in all money-changing paths to serialize callbacks/cashier actions. A pending attempt blocks another charge even after local expiry until a verified IPN arrives; expiry alone cannot prove no debit occurred. Merchant must reconcile an expired/unconfirmed transaction with VNPay rather than force-settling it locally. Confirmed failures allow a fresh attempt. A new reference never overwrites an older one. Refund API must reject VNPay payments until an actual gateway refund integration exists.

Steps:
1. Add focused tests for signing/tampering, amount/ownership, duplicate and failed IPNs; run red. Add OpenAPI.
2. Implement standard-library signing/config, transaction entity/repository, checkout and authenticated status APIs, public IPN and cashier guards. Add vi/en/default message keys.
3. Add VNPay option and result polling UI; keep charcoal/salmon, no leading icons, inline errors and accessible loading/retry states. Test checkout retry without duplicate subscriptions and result page trust boundary.
4. Run Maven tests including database policy/profile tests, database config PowerShell check where runtime exists, frontend build/lint/tests and mocked browser checkout. Document merchant env/HTTPS IPN setup and the live-test limitation without credentials. Update DESIGN.md.

Protocol reference: https://sandbox.vnpayment.vn/apis/docs/thanh-toan-pay/pay.html (PAY 2.1.0, amount ×100, URL-encoded sorted fields, HMAC-SHA512, IPN RspCode/Message).
